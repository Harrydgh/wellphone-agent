## 第三阶段：Agent 核心循环（已完成）

本阶段将页面感知和虚拟屏控制连接成目标驱动循环：Agent 每一步先观察当前页面，再由规划器选择动作，经过安全策略批准后执行，随后重新观察页面并验证结果。当前首个受控目标是“打开系统 WLAN 设置页面”。

```text
任务目标 → 观察页面 → 规划动作 → 安全检查 → 执行动作
              ↑                         ↓
              └──── 验证变化 / 重试 / 停止 ────┘
```

当前规则规划器只能生成点击目标、浏览列表、返回、完成和中止，不接收任意坐标。点击坐标必须从当前 UI Automator 页面中的可点击控件重新计算；观察显示与控制显示不一致、离开允许的 App、虚假完成、连续两次无页面变化或超过最大步数时都会停止。

保持手机亮屏并解锁后运行首个 Agent 任务：

```powershell
.\scripts\agent_test.ps1 -Target WLAN
```

2026-09-26 已完成真机验收：Agent 在虚拟屏中观察系统设置，自主选择并点击 `WLAN`，用 1 个动作进入 `.Settings$WifiSettingsActivity`，随后根据目标成功条件自动结束。每次观察、决策、动作和验证均写入 `logs/`，对应截图保存在 `screenshots/`。

这一阶段使用确定性的规则规划器验证 Agent 架构和安全边界，还没有调用云端 AI 模型。下一阶段将在不改变执行安全层的前提下，增加自然语言任务解析和模型规划器。

## 第四阶段：AI 模型规划器（代码完成，待实机验收）

本阶段增加自然语言安全目标解析和 OpenAI 模型规划器。用户任务必须先映射成本地白名单目标；模型只能在 `tap`、`scroll_down`、`abort` 三种结构化动作中选择，不能生成坐标、不能扩大 App 范围，也不能自行宣布任务完成。模型建议仍须经过第三阶段的本地安全策略，完成状态仍由手机 Activity 在本地验证。

为减少隐私暴露，模型请求不包含截图、完整页面文字、账号或周边 Wi-Fi 名称，只包含任务名称、当前 App/Activity、目标是否可点击、已浏览次数和允许动作，并显式设置 `store=false`。响应使用严格 JSON Schema；认证、额度和网络错误会转换为不包含凭据内容的本地提示。

使用默认模型运行：

```powershell
.\scripts\ai_agent_test.ps1 -Task "请帮我打开 Wi-Fi 设置"
```

也可以通过 `WELLPHONE_OPENAI_MODEL` 或脚本的 `-Model` 参数选择账户有权限使用的模型。项目使用 `OPENAI_API_KEY`，密钥不得写入代码、README、日志或 Git。

## 第五阶段：LangGraph 工作流与 DeepSeek（已完成）

本阶段在保留原有 `AgentLoop` 稳定基线的同时，新增 LangGraph 状态工作流。新流程由 `observe`、`plan`、`validate`、`execute`、`verify` 和 `finalize` 六个节点组成，并通过条件边完成成功、失败、重试和安全停止。每次运行使用独立 `thread_id` 和内存检查点，便于追踪同一次任务的状态变化。

DeepSeek 通过 LangChain 官方 `langchain-deepseek` 适配器接入。模型只能返回 `tap`、`scroll_down` 或 `abort`，点击目标仍必须等于本地白名单目标；坐标由 UI Automator 当前页面重新计算。模型不能直接调用 ADB、scrcpy 或任意坐标，所有动作仍须经过现有 `AgentSafetyPolicy`。

模型请求只包含任务、App、Activity、目标是否可点击和安全浏览次数，不上传截图、设备标识、完整页面文字或周边 WLAN 名称。API 错误不会把密钥或服务端敏感详情写入日志。

配置环境变量：

```powershell
$env:DEEPSEEK_API_KEY = "你的密钥"
$env:WELLPHONE_DEEPSEEK_MODEL = "deepseek-flash"
```

保持手机亮屏、解锁并在线后运行：

```powershell
.\scripts\langgraph_agent_test.ps1 -Task "请帮我打开 Wi-Fi 设置"
```

2026-09-27 已使用 `deepseek-flash` 完成独立 API 和真机端到端验收：LangGraph 在虚拟显示中观察系统设置，DeepSeek 返回受限制的 `tap WLAN` 动作，本地安全策略批准并执行 1 次点击，最终由本地 Activity 验证进入 `.Settings$WifiSettingsActivity`。对应截图和 JSONL 日志保存在 `screenshots/` 与 `logs/`。DeepSeek 偶发格式差异会在执行动作前进行一次安全重试，并由本地 Pydantic 严格校验；两次均失败则停止，不会点击手机。项目共 42 项自动测试通过。

## 第六阶段：通用任务、候选控件与人工确认（已完成）

本阶段将固定的 WLAN 单任务扩展为本地安全任务注册表，目前支持解析 WLAN、蓝牙、移动网络、我的设备和更多连接。每个任务独立声明允许的 App、可点击导航目标、成功 Activity、风险等级和是否需要人工确认；未注册的自然语言任务继续被拒绝。

模型不再只接收一个目标是否可点击，而是接收当前页面中经过本地任务白名单过滤的 `clickable_candidates`。候选只有一个时由本地确定性规则直接选择，多个候选时才交给 DeepSeek 或 OpenAI；模型只能从该列表选择目标，不能点击页面中的账号、权限或其他无关控件，也不能生成任意坐标。候选为空时只能安全滚动或中止。

LangGraph 增加 `approve` 节点。需要确认的点击会在执行前通过 `interrupt()` 暂停并保存线程检查点；用户批准后从同一节点恢复，用户拒绝则转换为 `abort`，不会向手机发送动作。命令行入口会展示任务、风险、动作、目标和原因，只有输入 `yes` 才批准。

2026-09-28 已完成多任务解析、候选控件约束、越权拒绝、单候选本地决策、瞬时 UI 树失配重试、批准后执行、拒绝不执行以及暂停恢复测试，项目共 52 项自动测试通过。真机已完成蓝牙、移动网络、我的设备和更多连接验收；MIUI 的蓝牙、我的设备和更多连接均使用 `.SubSettings`，因此由 Activity 与页面标题联合确认。移动网络会进入 `com.android.phone/.settings.MobileNetworkSettings`，项目仅为该任务增加这一精确系统包白名单，其他跨 App 行为仍会被拒绝。所有任务都只打开目标页面，没有修改开关、网络、SIM 卡或设备连接。

## 第七阶段：OCR 与复杂页面理解（已完成）

本阶段增加完全在电脑本地运行的 RapidOCR。每次观察先从虚拟屏截图，再将 OCR 文字区域与 UI Automator 控件树融合：两者重复时优先保留可执行、可信度更高的 UI 控件；UI 树缺失的价格、图片文字和自绘界面内容则由 OCR 补充。截图不会发送给 DeepSeek。

融合后的页面元素会先经过隐私过滤，隐藏手机号、邮箱、长订单编号、收货地址和联系人，再用于页面分类和候选动作生成。当前可识别首页、搜索、结果、店铺、商品、购物车、确认订单、支付、登录和权限页面。候选动作按低、中、高风险分级；加入购物车、选规格、结算和地址等需要确认，提交订单、立即购买和支付必须由用户接管，删除、密码和扩大权限相关项不会成为候选。

保持手机亮屏并解锁后，可运行只读真机识别：

```powershell
.\scripts\understand.ps1 -App com.android.settings
```

该命令只创建虚拟屏、采集一帧并在本地分析，不点击、不滑动、不调用 DeepSeek。输出包含页面类型、脱敏后的元素、候选动作及风险信息；调试截图和 JSONL 日志仍分别保存到 `screenshots/` 和 `logs/`。通用 OCR 候选标记为不可执行，避免文字框位置直接变成控制坐标；第八阶段仅对美团任务中的“选规格”和“加入购物车”两个精确白名单按钮开放高置信度、人工确认后的受控点击。

本阶段完成后，下一阶段才会把这些通用页面状态接入 LangGraph 的“观察—规划—确认—执行—验证”循环，并为外卖场景建立受限任务流程。提交订单和支付不会自动执行。

## 第八阶段：美团通用任务执行闭环（已完成）

本阶段新增独立于系统设置 Agent 的复杂 App 任务型 LangGraph。工作流仍由观察、规划、校验、人工确认、执行、重新观察和验证组成，但状态改为使用第七阶段的 `PageUnderstanding`。系统设置任务原有稳定流程没有被替换。

美团第一版固定使用精确包名 `com.sankuai.meituan`。DeepSeek 只能从本地任务过滤后的候选编号中选择，不能生成坐标、搜索词、店铺、商品、地址或支付动作。中文搜索词由命令行参数直接注入 scrcpy 控制通道，不经过 Shell，也不能被模型改写。

任务候选只保留首页、外卖、搜索、与搜索词明确匹配的结果、选规格、加入购物车和购物车导航。与任务无关的账号、会员、钱包、借钱、月付、账单和订单历史不会进入 DeepSeek 的任务载荷。普通 OCR 文字只能用于页面理解，不能执行点击；仅“选规格”和“加入购物车”两个按钮可在达到置信度阈值且用户明确确认后使用 OCR 定位，UI Automator 控件仍优先使用。规格弹窗出现后会隐藏背景中的“选规格”，避免重复点击。

工作流遇到登录、权限、确认订单或支付页面会停止。提交订单、地址修改、验证码、密码和支付不属于允许动作。任务只有在历史中已经执行“加入购物车”，并且重新观察确认当前为购物车页面，或规格弹窗中的加购按钮已消失且出现已选规格与购物车结算状态时才会成功结束；底部导航栏单独出现“购物车”不会被当成完成。

## 第九阶段：真实并发使用与稳定性验收（已完成）

本阶段为美团任务增加主屏并发监测。验收模式会在 Agent 使用虚拟显示时持续观察 `display 0`：用户在主屏切换微信、浏览器等其他 App 不会影响任务；如果系统将同一个美团任务迁移到主屏，监测器会记录冲突并在下一个动作发送前安全停止。主屏盔b连续三次失败时也会按失败关闭，不在不确定状态下继续点击。经过人工确认的动作会在真正点击前重新截图并重新定位同一控件；候选控件消失或页面已变成结算、支付等敏感页面时会拒绝使用旧坐标。商品页出现“加载中”时会只等待并重新观察，不把临时空页交给模型，也不向手机发送点击或滑动。如果进入美团滑块人机验证，则标记为人工接管并停止，Agent 不自动绕过验证。

任务还增加重复加购防护。商品页需同时出现与本次搜索词匹配的商品、“已选规格”、“去结算”，且“加入购物车”按钮已消失；店铺购物车状态则需同时出现本次匹配商品、“去结算”且没有“加入购物车”按钮，才会判定该商品已加购并直接停止。仅看到其他商品或底部“购物车”导航不会触发完成。

保持手机亮屏、解锁并在线后运行：

```powershell
.\scripts\concurrency_acceptance.ps1 -Query "库迪咖啡经典拿铁"
```

每次验收启动时会先结束美团上一次遗留的运行状态，再在虚拟屏从首页启动。该操作不会清除登录、购物车或 App 数据。

运行期间可以在手机主屏使用与美团不同的 App，但不要在主屏打开美团。任务结束后会在 `reports/` 生成 JSON 验收报告，包含任务结果、步数、最终页面、动作历史、主屏出现过的 App、切换次数、同 App 冲突和监测异常。报告与运行截图一样不提交到 Git。

## 安全边界

- 默认不向主显示 `display 0` 发送输入。
- 自动化动作必须通过绑定虚拟显示的 scrcpy 控制连接发送。
- 第一版不执行支付、删除、账号或权限变更。
- 每次运行都应保留动作日志，且提供立即停止方式。
